# 测试与质量门禁

质量目标不是“单元测试很多”，而是证明领域不变量、适配器替换性、真实运行时行为、失败原子性和数据质量。

## 测试金字塔

| 层级 | 关注点 |
| --- | --- |
| 单元测试 | 纯模型、校验、状态机、摘要、转换和查询表达式 |
| 契约测试 | 所有 Repository、ArtifactStore、Backend、Policy、Trainer 等实现共享行为 |
| 集成测试 | SQLite/S3/PostgreSQL、真实 SDK、GPU、队列和工作节点 |
| 端到端测试 | 资产 → 场景 → 任务 → Episode → 数据集 → 模型 → 评测 |
| 性能测试 | FPS、环境步、写入吞吐、延迟、显存、恢复时间和成本 |
| 真机验收 | 坐标、控制、安全、时间同步、失败记录和回滚 |

## 核心质量门禁

```bash
python -m ruff format --check .
python -m ruff check .
python -m mypy
python -m pytest tests/unit tests/contract
python -m pytest tests/integration -m 'not gpu and not robot'
python -m mkdocs build --strict
python -m build
python -m twine check dist/*
```

GPU、后端和真机测试在带标签的专用 runner 运行，不把不可用硬件伪装成普通测试失败。

## 领域不变量测试

必须覆盖：

- 未知字段、非法标识、NaN/Inf 和无时区时间被拒绝；
- 四元数归一化、惯量正定和关节图无环；
- 信号 dtype/shape/unit/frame 精确一致；
- Episode 步骤、时间戳、首末帧和成功/失败语义；
- 同内容同摘要、不同内容不同摘要；
- 不可变资源冲突与幂等注册。

属性测试适合覆盖随机合法/非法图、浮点边界和序列不变量。

## 状态机测试

为每种 Job 枚举所有合法边和非法边：

- 成功路径；
- 每个阶段失败；
- 排队和运行中取消；
- finalizing 时中断；
- worker 失联与租约回收；
- 重复消息、重复提交和重复取消；
- resume 的可恢复与不可恢复条件。

## 故障注入

至少模拟：

- 制品写一半磁盘满；
- 上传成功但元数据事务失败；
- 元数据成功但事件重复；
- 工作节点心跳中断；
- GPU OOM；
- 后端 step 抛异常；
- 训练检查点损坏；
- 网络超时后客户端重试。

验收重点是没有伪完整资源、没有重复发布、状态可解释且资源可清理。

## 数据质量测试

小型固定黄金数据集用于验证：

- Episode 模式和时间语义；
- 多模态对齐；
- 数据导出 round-trip；
- 训练 loader 窗口和动作对齐；
- 指标计算；
- 数据切分无实体泄漏。

## 后端基准

每个后端报告：

- 固定任务的 physics FPS / environment steps per second；
- 不同相机、分辨率和模态下的渲染吞吐；
- 环境数—显存—吞吐曲线；
- Episode 写入和压缩吞吐；
- 固定种子重复运行误差；
- 长时间运行资源泄漏。

性能回归使用相对阈值和硬件标签，不跨不同 GPU 直接比较绝对值。

## 文档测试

- `mkdocs build --strict` 无孤立导航和断链；
- 所有代码片段经过语法检查；
- 快速开始在干净环境可执行；
- API 签名与公开实现自动比对；
- 已删除接口不再出现在全文搜索与示例中。

## 合并要求

任何公共 API、领域模型、状态机或数据格式变更必须同时包含：

- 设计说明与失败语义；
- 单元与契约测试；
- 用户指南和 API 文档；
- 明确迁移工具或主版本变更；
- 对性能、存储和可复现性的影响评估。
