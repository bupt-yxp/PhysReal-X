## 证据边界

软件功能验收、仿真数值验证、真实物理验证、真机策略验证是不同结论。
反向建模 USD 的尺寸、结构和物性是模型先验；它们不能作为验证自己的独立实测真值。
仿真中的力觉与事件为模拟数据，日志回放不能被记为现场真机执行。
真实照片或普通深度序列不能提供未采集的质量、驱动力、摩擦或机器人控制日志。

六个 Notebook 必须产生实际结果并明确失败，禁止 `None` 输入、捕获异常后继续打印成功、
将未安装的方法名称当作实现，以及将 CPU 基线标成某篇论文的 SOTA 复现。
Notebook 输出统一指向同一 `.physrealx` 工作区中的不可变资产和结果。

## 开源方法选择

- [ArtGS](https://articulate-gs.github.io/)：已公开的多部件几何与运动恢复，作为高斯重建方法；需要可用 CUDA 与其扩展。
- [CoACD](https://github.com/SarahWeiii/CoACD)：碰撞感知凸分解；项目运行锁定已验证版本。
- [MuJoCo](https://github.com/google-deepmind/mujoco)：真实刚体动力学与同步渲染。
- [LeRobot ACT](https://github.com/huggingface/lerobot)：执行官方 CVAE/Transformer 网络、L1 + KL 训练与动作块闭环控制，保存权重、来源、依赖及实际配置。
- [DINO-WM](https://github.com/gaoyuezhou/dino_wm)：已接入官方 DINOv2 编码器与因果 ViT 预测器，真实执行动作条件训练、状态/图像预测及反事实；平台残差头与可视化解码器单独记录。

主机设备访问复核（2026-09-07）：现有 PhysReal-X Conda 环境能识别两张 RTX 4090；
使用空闲 GPU 0。受限执行隔离中的 CUDA 探测会失败，不能据此判断主机没有 GPU。
GPU 方法仍需检查其实际依赖与执行结果；现场真机测试不能由软件测试替代。

## 当前条件下的范围和待验事项

- **独立物理实测与真机**：当前没有真机或独立质量/受力测量。这些现场认证不纳入本轮离线验收；USD 与仿真不得自证真实物性。
- **外观范围**：已保留 UV、纹理、法线/ORM 贴图与可携带 PBR 参数。MuJoCo 原生 OpenGL 采用纹理与标量高光参数，不能等同原始 MDL 光照/划痕程序。已配准高斯是单物体外观，不是全场景光线追踪。
- **运动与物性范围**：两次实拍只激发下层抽屉；上层独立运动来自 USD。高斯合并静止组不能随意拆成未观测的新运动；渲染器遇到这种运动会拒绝。当前单关节辨识覆盖等效惯量、阻尼和库仑摩擦，尚无一般柔性材料/刚度辨识。
- **泛化范围**：当前验收对象为 cabinet2 与一维接触推杆。未见资产泛化、通用机械臂/VLA/RL、任意语言规划不因已有数据接口而被视为完成。

六个 Notebook 的执行证据、模拟预测质量与真实现场认证分别记录。PPT 的概念范围不能直接作为已验证的系统性能结论。
