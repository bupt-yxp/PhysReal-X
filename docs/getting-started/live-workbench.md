# 六模块运行工作台

网页工作台接受用户的输入，在服务器上排队执行 PhysReal-X 的六个真实模块，并返回**本次任务**的动画、报告、制品索引和错误日志。它调用仓库已有的 Notebook 执行器和 SDK；Notebook 是计算流程，不是网页预存结果的来源。

当前工作台部署在运行项目的机器上。GitHub Pages 只托管静态文档，不能运行 Python、MuJoCo、Blender 或 GPU 训练。按以下步骤启动执行服务后，打开[本机工作台](http://127.0.0.1:8765/)；如果工作台在远程服务器，请先建立 SSH 端口转发。

```bash
cd PhysReal-X
conda activate PhysReal-X
python -m ipykernel install --sys-prefix --name physreal-x --display-name PhysReal-X
MUJOCO_GL=egl python -m examples.web_app --host 127.0.0.1 --port 8765
```

远程服务器上的服务仍只监听 `127.0.0.1`。在自己的电脑上运行：

```bash
ssh -N -L 8765:127.0.0.1:8765 用户名@服务器地址
```

然后在本机浏览器打开 `http://127.0.0.1:8765/`。网页显示服务器和 GPU 状态。若 GPU 不可用，需要先修复该服务器的驱动与运行环境；服务在线并不等于重建或训练能够完成。

## 提交一次任务

1. 选择目标模块。工作台会显示它的真实上游链：**01 → 02** 或 **03 → 04 → 05 → 06**。
2. 填写每个阶段的参数。模块一可指定服务器上的 ArtModeling 数据目录，或上传包含 `can.start` 与 `can.end` 的 ZIP；模块二可上传含 `img` 的视频目录 ZIP。模块三可选场景并填写任务，模块四可选 MuJoCo/Isaac Sim，模块五可设置训练步数，模块六可设置采样和评测回合数。
3. 提交后查看任务 ID、排队与运行状态。每个任务在服务器依次执行其上游和目标模块，失败时停止，不用旧结果冒充成功。
4. 任务完成后查看**本次生成**的图像、GIF、指标与制品下载。结果索引保存在 `workspace/web/jobs/<任务 ID>/result.json`，大文件留在 `.physrealx` 不可变制品库中。

网页任务使用共享项目工作区，因此服务器一次只运行一条模块链。此安排防止并发任务互相覆盖 Notebook 的中间产物；队列和任务状态会在网页中显示。服务重启时未完成任务标记为中断，需重新提交。

如需读取项目目录之外的数据，可在启动前设置 `PHYSREALX_WEB_INPUT_ROOTS`，值为用系统路径分隔符连接的允许目录。默认只允许 `examples/` 和工作台上传目录。若服务需要监听非本机地址，必须设置 `PHYSREALX_WEB_TOKEN`；优先使用本机监听加 SSH 端口转发。

完整重建、仿真和训练依赖本机数据、模型与 GPU；[历史示例快照](demos.md)只能用于浏览既有结果，不能代替本次任务的执行。
